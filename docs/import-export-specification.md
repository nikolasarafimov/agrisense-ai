# Import/Export Specification

## Project

AgriSense AI – Intelligent System for Analysis and Recommendations in Agriculture

## Team

Team 38

---

## 1. Overview

AgriSense AI provides import and export functionality for the main agricultural data managed by the application:

- Crops
- Parcels
- Activities

The functionality allows authenticated users to:

- Export crops, parcels, and activities as CSV files
- Export all supported agricultural data in a single Excel workbook
- Import crops, parcels, and activities from CSV files
- Import all supported entity types from an Excel workbook
- Perform bulk data transfer and backup operations

All import and export operations are user-specific.

The authenticated user is determined from the JWT security context. The client does not provide a `userId` parameter.

---

## 2. Supported File Formats

| Format | Extension | Purpose |
|---|---|---|
| CSV | `.csv` | Individual crop, parcel, or activity import/export |
| Excel | `.xlsx` | Combined import/export of crops, parcels, and activities |

Legacy `.xls` files are not supported.

---

## 3. Authentication and Data Ownership

All import and export endpoints require an authenticated user.

The backend determines the current user from the JWT-based Spring Security context.

This means:

- A user can export only their own data
- Imported records are automatically assigned to the authenticated user
- A `userId` request parameter is not accepted
- User ownership information from uploaded files is not trusted
- Imported database IDs are not reused

New IDs are generated by the database for imported records.

---

## 4. CSV Format

CSV files use the following conventions:

- Encoding: UTF-8
- Delimiter: comma (`,`)
- Header row: required
- The first row is treated as the header and is not imported
- LF and CRLF line endings are supported
- Standard CSV quoting is supported
- Fields containing commas, quotes, or line breaks are escaped using double quotes

Empty values may exist syntactically in a CSV file, but required application fields must contain valid values.

Rows containing invalid required data are skipped and reported in the import result.

| Method | Endpoint | Result |
|---|---|---|
| GET | `/api/data/export/crops` | Crop CSV |
| GET | `/api/data/export/parcels` | Parcel CSV |
| GET | `/api/data/export/activities` | Activity CSV |
| GET | `/api/data/export/excel` | Combined Excel workbook |

All export operations use the currently authenticated user.

---

## 6. CSV Export Responses

CSV responses use:

```text
Content-Type: text/csv;charset=UTF-8
```

The response also contains a `Content-Disposition` header so the file is downloaded as an attachment.

Example:

```text
Content-Disposition: attachment; filename="crops.csv"
```

## 7. Crop CSV

### 7.1 Export File Name

```text
crops.csv
```

### 7.2 Structure

```csv
id,name,type,plantingDate
1,Wheat,Grain,2026-03-15
2,Corn,Grain,2026-04-01
3,Tomato,Vegetable,2026-05-10
```

### 7.3 Fields

| Field | Required for Import | Validation |
|---|---|---|
| `id` | No | Exported identifier; ignored during import |
| `name` | Yes | Maximum 100 characters |
| `type` | Yes | Maximum 100 characters |
| `plantingDate` | Yes | ISO date in `yyyy-MM-dd` format |

### 7.4 Supported Import Structures

CSV exported by AgriSense AI:

```csv
id,name,type,plantingDate
1,Wheat,Grain,2026-03-15
```

CSV without an ID column is also supported:

```csv
name,type,plantingDate
Wheat,Grain,2026-03-15
```

The imported `id` value is never reused.

## 8. Parcel CSV

### 8.1 Export File Name

```text
parcels.csv
```

### 8.2 Structure

```csv
id,location,size,soilType
1,North Field,2.5,Loam
2,South Field,4.2,Clay
```

### 8.3 Fields

| Field | Required for Import | Validation |
|---|---|---|
| `id` | No | Exported identifier; ignored during import |
| `location` | Yes | Maximum 200 characters |
| `size` | Yes | Finite numeric value greater than zero |
| `soilType` | Yes | Maximum 100 characters |

### 8.4 Supported Import Structures

CSV exported by AgriSense AI:

```csv
id,location,size,soilType
1,North Field,2.5,Loam
```

CSV without an ID column is also supported:

```csv
location,size,soilType
North Field,2.5,Loam
```

The following parcel sizes are invalid:

```text
0
-1
NaN
Infinity
```

The size must be a finite number greater than zero.

## 15. Excel Import

Excel import uses the following endpoint:

```text
POST /api/data/import/excel
```

The workbook is uploaded using multipart form data with the field:

```text
file
```

The supported workbook format is:

```text
.xlsx
```

The expected sheet names are exactly:

```text
Crops
Parcels
Activities
```

The first row of each sheet is treated as the header.

The Excel import format corresponds to the workbook generated by the AgriSense AI export functionality.

If one of the supported sheets is not present, that sheet is skipped while the remaining supported sheets can still be processed.

---

## 16. Excel IDs

The first column of each exported sheet contains the database ID.

During import, these IDs are ignored.

For example:

```text
ID = 25
```

does not cause the newly imported record to receive ID `25`.

Instead, the database generates a new identifier.

This prevents:

- Primary key conflicts
- Overwriting existing records
- Importing ownership relationships through IDs

---

## 17. Date Handling

Crop planting dates and activity dates use Java `LocalDate`.

The canonical text representation is:

```text
yyyy-MM-dd
```

Example:

```text
2026-09-12
```

CSV imports must use this format.

For Excel imports, the backend supports:

- Excel cells formatted as dates
- Text cells containing an ISO date

Examples of valid dates:

```text
2026-01-01
2026-05-20
2026-12-31
```

Examples of invalid values:

```text
12/09/2026
09-12-2026
2026-99-99
not-a-date
```

Invalid or missing required dates cause the affected row to be skipped.

---

## 18. Crop Import Validation

A crop is imported only when all required values are valid.

Requirements:

- `name` must be present
- `name` must not exceed 100 characters
- `type` must be present
- `type` must not exceed 100 characters
- `plantingDate` must be present
- `plantingDate` must contain a valid ISO date

Example of an invalid crop:

```csv
1,,Grain,2026-03-15
```

Reason:

```text
Crop name is required.
```

---

## 19. Parcel Import Validation

A parcel is imported only when:

- `location` is present
- `location` does not exceed 200 characters
- `size` is present
- `size` is numeric
- `size` is finite
- `size` is greater than zero
- `soilType` is present
- `soilType` does not exceed 100 characters

Example:

```csv
1,North Field,0,Loam
```

is rejected because:

```text
Parcel size must be greater than zero.
```

---

## 20. Activity Import Validation

An activity is imported only when:

- `description` is present
- `description` does not exceed 255 characters
- `date` is present
- `date` contains a valid ISO date
- `type` is present
- `type` does not exceed 100 characters

Example:

```csv
1,Irrigation completed,not-a-date,Irrigation
```

is rejected because the date is invalid.

---

## 21. Import Processing

Import processing is performed row by row.

A problem with one row does not automatically prevent other valid rows from being imported.

For every processed row, the backend either:

- Saves the valid record
- Skips the invalid record and records an error message

This allows partially valid files to be processed.

---

## 22. Import Result

Import operations return a JSON summary.

Example:

```json
{
  "imported": 3,
  "skipped": 1,
  "errors": [
    "Line 4: Parcel size must be greater than zero."
  ]
}
```

### Response Fields

| Field | Description |
|---|---|
| `imported` | Number of records successfully imported |
| `skipped` | Number of records that could not be imported |
| `errors` | Error messages describing skipped records |

For Excel imports, error messages identify the relevant sheet and row.

Example:

```text
Parcels row 4: Parcel size must be greater than zero.
```

---

## 23. CSV Escaping

During export, string values are escaped when necessary.

A field is wrapped in double quotes when it contains:

- A comma
- A double quote
- A line break

Example value:

```text
Field near house, section A
```

is exported as:

```csv
"Field near house, section A"
```

A double quote inside a field is escaped by doubling it.

---

## 24. User Ownership During Import

Uploaded files cannot specify the owner of imported records.

The backend automatically executes:

```text
record.user = authenticatedUser
```

for every successfully imported entity.

This prevents one user from importing data into another user's account.

---

## 25. User Ownership During Export

Export queries use the authenticated user when retrieving records.

Conceptually:

```text
findByUser(authenticatedUser)
```

is used for crops, parcels, and activities.

This ensures exported files contain only records belonging to the current user.

---

## 26. File Size Limits

The backend multipart configuration limits uploads to:

```text
Maximum file size: 10 MB
Maximum request size: 10 MB
```

These limits are configured through Spring Boot.

---

## 27. Security Considerations

The import/export implementation follows these security principles:

- Authentication is required
- JWT determines the active user
- `userId` values are not accepted from the client
- User ownership cannot be selected through an uploaded file
- Imported database IDs are ignored
- New IDs are database-generated
- Required fields are validated
- Invalid records are skipped
- File upload size is limited
- Export queries are user-scoped

## 28. Implementation Technologies

The import/export functionality uses:

- Java 21
- Spring Boot
- Spring Security
- JWT authentication
- OpenCSV
- Apache POI
- Java `LocalDate`
- PostgreSQL

OpenCSV is used for CSV parsing.

Apache POI is used for `.xlsx` workbook creation and parsing.

AgriSense AI provides authenticated and user-scoped import/export functionality for crops, parcels, and activities.

The final implementation supports:

- Crop CSV import and export
- Parcel CSV import and export
- Activity CSV import and export
- Combined Excel export
- Combined Excel import
- UTF-8 CSV processing
- `.xlsx` Excel workbooks
- ISO `LocalDate` handling
- Validation of imported records
- Per-row error reporting
- User ownership protection
